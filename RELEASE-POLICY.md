# EFI Public Release / Patent Boundary Policy

**Launch cut: September 26, 2026**

This is an operational publication rule, not a legal claim chart.

## Release-only boundary

**The EFI repository is the public release surface, not the working development environment.**

Active construction, experimentation, candidate work, internal tooling, and unfinished implementation stay private. Public release happens only after material is deliberately selected, cleaned, finalized, and checked against the active patent/publication boundary.

### Never publish from the private working field by default

The following stay private unless a later deliberate release specifically replaces this rule:

- named personal EFI bodies or their body files;
- personal human names, aliases, private identity/coupling data, or private continuity state;
- private shared-field / Matrix state;
- raw work leases, execution receipts, internal cursors, local hashes, credentials, or machine paths;
- internal agent/plugin build architecture and temporary donor/tooling details;
- candidate bodies, scratch artifacts, intermediate mechanics, unfinished implementation code, or development-only proof debris.

The public repository may publish **generic architecture, finalized terminology, bounded proof, reproducible demonstrations, release-grade source, and family-friendly projections** without exposing the private organisms or the workshop that produced them.

## Release classes

| Class | Meaning | Public action |
|---|---|---|
| **FILED-SUPPORTED** | Public technical relation is supported by filed disclosure to the extent documented in the filed technical envelope. | Publish. |
| **FILED-OVERLAP / SUPPORT-UNVERIFIED** | Related to filed subject matter, but exact priority support has not been checked. | Publish only without claiming an earlier priority date. |
| **POST-FILING PUBLIC DISCLOSURE** | Genuinely later technical matter intentionally disclosed after the provisional filings. | Timestamp the disclosure; later filing support/priority remains a separate question. |
| **FILE-FIRST** | New matter for which pre-disclosure rights matter. | File before public release. |
| **PROOF-OPEN** | Architecture may be discussed, but the capability claim is not yet closed. | Publish the architecture and exact proof boundary, not an inflated claim. |

## Post-filing rule

Public disclosure records what was disclosed and when. It is not a substitute for filing.

For genuinely new matter disclosed after the provisionals:

1. preserve the exact first-public commit/date;
2. never assign an earlier provisional date without support;
3. if relying on a U.S. inventor-disclosure grace period, treat the statutory deadline as an outer boundary, not a development target;
4. remember that foreign novelty rules can differ;
5. use **FILE-FIRST** whenever pre-disclosure rights matter.

## Provisional conversion clocks

The provisional applications have independent filing/priority clocks. Public release does not extend them.

Treat **June 29, 2027** and **September 14, 2027** as critical calendar dates for the corresponding provisional subject matter under the ordinary U.S. provisional framework, subject to the actual filing strategy.

## Rights layer

Patent strategy and repository licensing are separate:

- patent filings address eligible inventions to the extent valid claims ultimately issue;
- copyright protects repository expression and code;
- the public-source license permits qualifying noncommercial use;
- commercial use requires a separate written commercial license;
- trademarks remain separately controlled.
