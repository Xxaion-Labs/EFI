## Why this exists

A brand is useless if every new artifact has to rediscover it.

The public EFI Skills layer carries reusable production rules into future work so GitHub pages, reports, white papers, presentations, diagrams, release graphics, and other public surfaces begin inside the same visual system instead of being restyled afterward.

## EFI Visual System

**Path:** [skills/efi-visual-system/](efi-visual-system/)

The Skill applies:

- canonical palette and semantic color roles;
- reduced / standard / full visual-density profiles;
- motif semantics;
- public proof/status presentation rules;
- surface recipes for GitHub, web, documents, presentations, social graphics, Skill UI, and terminal output;
- a final brand-quality gate.

It explicitly does **not** get to change the meaning of technical claims. Visual force follows evidence force.

### Trigger examples

- "Make this EFI white paper."
- "Turn this into an EFI presentation."
- "Brand this GitHub README."
- "Make an announcement graphic for this release."
- "Apply the EFI visual system to this report."
- "Build a public EFI Skill."
