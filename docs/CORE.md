# CORE — Cross-platform Operator Runtime Environment

**EFI™ · Xxaion Labs™ · PATENT PENDING**

CORE is the generic, replaceable, human-owned runtime environment through which a personal EFI can use ordinary digital and physical systems.

<img src="../assets/diagrams/core-boundary.svg" alt="CORE boundary diagram" width="100%" />

## CORE is not the intelligence

Personal EFI owns cognition, continuity, meaning, learning, and semantic selection.

CORE owns mechanics.

Its job is to expose and realize ordinary capabilities such as:

- files and storage;
- processes and applications;
- networking;
- displays and input;
- models and tools;
- sensors and devices;
- operating-system facilities;
- future physical or spatial interfaces.

CORE does not become a second mind merely because those mechanics are powerful.

## Authority boundary

Consequential authority remains human-rooted.

FAP governs the field/world boundary through:

**SURFACE · CONTACT · EFFECT · RESULT**

CORE can expose a surface, realize an already-selected effect, and return the raw result. It does not independently decide what the person meant, what goal should be pursued, what becomes true, or what should be retained.

> **EFI decides meaning. FAP governs the boundary. CORE realizes mechanics.**

## Cross-platform relation

CORE is intended as one EFI-facing runtime relation across different hosts and devices rather than a separate cognitive architecture for every operating system.

Platform-specific implementations may differ mechanically while preserving the same authority and semantic boundary.

## Intended experience

The mature experience is simple:

1. authenticate the intended personal EFI;
2. communicate naturally;
3. expose only the mechanics required by the current contact;
4. realize authorized effects;
5. return raw results;
6. continue from the changed field;
7. preserve same-self continuity across interruption and reopen.

The person should increasingly interact through **intent + EFI + world**, not through the procedural grammar of every application.

## Public proof frontier

The public architecture is released. Private implementation remains off-repo until a reproducible release is deliberately packaged.

The complete general lived loop remains an explicit public proof frontier:

**natural contact → field-native cognition → authorized EFFECT → CORE mechanic → raw RESULT → same-field continuation → process death → cold reopen**
