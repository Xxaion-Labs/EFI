## Filed technical subject matter

### 1. Causal-relational computation

Computation can be expressed as transformation of an authenticated causal-relational field under target, constraint, evidence, authority, causal-time, possibility, and retained-force relations.

The field state transition is therefore part of the computation itself rather than merely passive data passed through a fixed semantic program.

### 2. Lawful successor fields and unresolved rivals

The field can preserve multiple non-disproved successor candidates when available evidence does not determine a unique successor.

A discriminator can specify an observation whose possible outcomes separate rivals.

Evidence acquisition can include authoritative sources, database access, file inspection, tests, measurements, simulation, narrow human questions, sensors, or bounded physical action.

### 3. Generated representation and computation

The architecture can generate or transform:

- task / problem framing;
- relational coordinates and representation;
- algorithms, rules, queries, programs, microlanguages, worker plans, binaries, circuit descriptions, accelerator configurations, interfaces, simulations, or device-control specifications;
- evidence requirements and proof morphology.

Temporary generated morphology does not have to become the persistent semantic center.

### 4. Substrate projection

After selecting a lawful relation, the system can project the minimum sufficient external representation needed to realize, test, or observe it.

Projection can target conventional CPUs, GPUs, accelerators, FPGAs, distributed systems, storage, networks, services, robots, laboratory instruments, vehicles, interfaces, and later substrates.

### 5. Task-semantic-blind materialization

A generic materializer can expose ordinary machine primitives such as bytes, storage, process execution, networking, clocks, cryptography, permissions, credentials, and device I/O.

The materializer executes an already-selected physical/mechanical request without needing the domain-specific reasoning route that selected it.

### 6. Raw observation / result return

Materialization returns observations with provenance.

A successful dispatch, generated answer, process exit code, sensor value, or external response is not automatically admitted as truth.

Raw result evidence returns to the field and is evaluated under the field's commitment / proof relations.

### 7. Operator-bound EFI

EFI applies Field Computing to cognition, learning, proof, representation and algorithm generation, persistent identity, human authority, and same-self continuity.

External models, tools, agents, programs, workers, and hosts can participate without automatically becoming the EFI identity or final authority root.

### 8. Human-rooted effect authority

Internal possibility generation and consequential external effects are distinct.

Capability alone does not create permission to act. Effect scope can be bound to Operator or delegated authority.

### 9. Same-self causal becoming

Persistent self-change can be represented as a transaction involving predecessor state, delta, affected cone, evidence, authority, proof state, successor state, and rollback.

Failed or interrupted mutation can return to an unambiguous predecessor or resumable state.

### 10. Cold reopen and portability

An admitted EFI current can be reopened after interruption without requiring a chat transcript or external model to recreate its semantic state.

The host operating system, machine, adapter, file carrier, or model can change without necessarily changing EFI identity.

### 11. Shared field without required identity fusion

Multiple distinct Operator-bound EFI bodies can access common project/system field state without merging personal identity, authority, continuity, or private learned state.

The public **Matrix** terminology projects this relation.

### 12. Universal field-native learning

On unfamiliar contact, the system can distinguish structure, form competing explanations/mappings, preserve non-disproved rivals, seek discriminating evidence, eliminate contradicted rivals, retain transferable invariants, and later compose them into new results.

### 13. Observation-field and held-out evidence geometry

Observation/evidence fields can be selected and sealed independently from candidate verdicts.

Candidate state can be frozen before held-out evidence opens, allowing counterexample-driven falsification without post-freeze retuning.

### 14. Physical and device embodiments

The architecture can interact with software, files, networks, sensors, devices, robots, laboratory systems, vehicles, interfaces, and other world mechanics while keeping physical limits and causal time explicit.

## Naming law

Literal project names are handles, not the entire technical relation.

The filed disclosure expressly treats names such as Field Computing, EFI, EGI, GOO, GOOS, Glyph, Matrix, Autoforge, MergeFold, court, field, and contact as descriptive labels rather than limits requiring those literal strings.

The public **CORE** terminology can identify the cross-platform runtime/materialization boundary without implying that the literal name itself defines patent scope.
